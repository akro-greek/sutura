# RFC 001: From voxel to citation

Status: ready for community feedback

## Problem

The Vesuvius ecosystem has strong tooling for CT access, segmentation,
flattening, and ink detection. Once characters are read, evidence often moves
into PDFs, messages, and isolated transcriptions. Researchers need a verifiable
bridge from a location on the papyrus to a reading, a proposed corpus parallel,
and a reviewed scholarly assertion.

## Proposed workflow

1. Import an artifact manifest and transcription without rewriting either.
2. Anchor columns and lines to regions on a flattened image.
3. Preserve diplomatic, EpiDoc, Unicode, normalized, and accent-folded forms.
4. Generate explainable corpus candidates from forms, lemmas, and optional
   embeddings.
5. Let invited reviewers accept, reject, or request work with a written reason.
6. Export accepted assertions to EpiDoc, JSON-LD, CSV, and Web Annotation.

## Trust model

Algorithms produce candidates, never final readings. Every candidate names its
sources, algorithm version, and evidence. Every accepted assertion records its
reviewer and timestamp. Revisions and decisions are append-only.

## First dataset

PHerc. 1667 is the first complete vertical slice because official flattened
renderings and transcription artifacts are available from the Vesuvius
Challenge data browser. The repository initially includes only an invented
demonstration fixture; importing official artifacts requires verification of
their current files, checksums, citations, and licenses.

## Interoperability

Sutura publishes JSON Schemas and accepts EpiDoc XML and JSONL. Stable external
identifiers include PHerc, DCLP, Trismegistos, and CTS URNs. The application is
implemented in Rails, but no downstream researcher must use Ruby.

## Questions for the community

- Which transcription artifact should be treated as the canonical starting
  point for PHerc. 1667?
- Are line polygons available, or should the project publish manual anchors?
- Which uncertainty distinctions must remain visible in the reviewer UI?
- Which EpiDoc validation profile should gate exports?
- What evidence is most useful when evaluating an intertextual candidate?

## MVP boundary

The MVP does not process CT volumes, train ink models, reconstruct lacunae, or
publish automated claims. It provides the review and interoperability layer
after virtual unwrapping and reading.
